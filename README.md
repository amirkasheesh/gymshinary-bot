# gymshinary-bot

## Инструкция по запуску и настройки бота

Следующие шаги предназначены для локальной разработки. `dotnet user-secrets` хранит секреты вне каталога проекта и Git, но не шифрует их и предназначен только для разработки. Доступ к локальной учётной записи и файлам секретов ограничивается средствами ОС. См. [документацию Microsoft](https://learn.microsoft.com/en-us/aspnet/core/security/app-secrets?view=aspnetcore-9.0#use-the-secret-manager-tool).

Для запуска текущей технической основы необходимы:

- установленный .NET 9 SDK;
- доступ к NuGet для восстановления зависимостей и к Telegram Bot API;
- токен Telegram-бота, полученный через BotFather.

---

### 1)
Из корня репозитория:

```bash
cd src/Gymshinary.Bot
```

### 2)
Записать токен бота:

```bash
dotnet user-secrets set "BotConfiguration:BotToken" "ВАШ_ТОКЕН_ОТ_BOTFATHER"
```

### 3)
Проверить, что секрет сохранился:

```bash
dotnet user-secrets list
```

Должно показать примерно:

```text
BotConfiguration:BotToken = 123456789:ABC...
```

### 4)

Теперь нужно запустить:

```bash
dotnet run
```

Тогда код:

```csharp
builder.Services.Configure<BotConfiguration>(
    builder.Configuration.GetRequiredSection("BotConfiguration"));
```

сам подхватит значение из User Secrets, а здесь:

```csharp
botConfig.BotToken
```

окажется настоящий токен

---

**Проверка работоспособности.** Пока приложение запущено, открыть личный чат с соответствующим ботом в Telegram и отправить `/start`.

**Ожидаемый результат.** Бот отвечает: «Добро пожаловать в амбициозный проект по ведению дневника в тренажерке!». Команда `/help` возвращает справку, а неизвестная команда — сообщение с предложением воспользоваться `/help`.

Эта проверка подтверждает работу начальной серверной основы и обмен сообщениями через Telegram Bot API. Тренировочная логика, служебные операции и хранение данных в PostgreSQL будут реализованы на следующих этапах.

Для остановки приложения нажать `Ctrl+C` в терминале.

## Секреты в среде развёртывания

В среде развёртывания токен Telegram и пароль PostgreSQL передаются вне исходников и Git через конфигурацию этой среды: например, переменные окружения, файлы секретов контейнера или серверное хранилище секретов. Для токена можно использовать ключ `BotConfiguration__BotToken`. Права доступа настраиваются средствами выбранной среды; сами переменные окружения также не обеспечивают шифрование секретов. User Secrets для развёртывания не используется.

Секреты не включаются в образ приложения, публикуемые конфигурации, ответы бота и логи. Для замены секрета обновляется конфигурация и перезапускается приложение без изменения исходников и пересборки. Отзыв токена на стороне Telegram выполняется отдельно; Gymshinary отвечает за прекращение использования прежнего значения. Команда `dotnet user-secrets list` из локальной инструкции показывает значения секретов — её вывод не следует публиковать.

## Доработка требований безопасности

Доработаны семь требований: `SR-01`, `SR-02`, `SR-04`, `SR-05`, `SR-06`, `SR-07` и `SR-09`. Уточнены принадлежность родительских объектов, ограничения оператора, достоверность истории, источник обновлений Telegram, защита секретов, границы атомарности одной команды и восстановление из резервной копии. В [наборе требований](documents/SECURITY_REQUIREMENTS.md) сохраняются 10 пунктов со стабильными ID; описанные критерии приёмки не означают, что защита уже реализована или проверена.
