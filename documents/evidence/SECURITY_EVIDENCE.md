# Цепочка подтверждения свойств безопасности ядра и контроля доступа (S07)

### Свойство и механизм
- Требуемые свойства:
  - [SR-01](../SECURITY_REQUIREMENTS.md#sr-01-доступ-к-пользовательским-данным-по-владельцу) / [D-01](../DESIGN_DECISIONS.md#d-01-серверная-авторизация-по-владельцу-и-отдельные-полномочия-оператора): разграничение доступа к программам, шаблонам, сессиям и результатам подходов строго по владельцу (`UserId`). Запрет привязки к чужим родительским объектам. Ограничение служебного доступа оператора только техническими метаданными.
  - [SR-02](../SECURITY_REQUIREMENTS.md#sr-02-контролируемое-служебное-прерывание-сессии) / [D-01](../DESIGN_DECISIONS.md#d-01-серверная-авторизация-по-владельцу-и-отдельные-полномочия-оператора) / [D-02](../DESIGN_DECISIONS.md#d-02-сериализация-изменений-сессии-и-атомарное-служебное-прерывание): служебное прерывание сессии разрешено только оператору из конфигурации с непустой причиной, сохраняет результаты подходов и атомарно фиксирует запись действия с откатом при сбое сохранения аудита.
  - [SR-03](../SECURITY_REQUIREMENTS.md#sr-03-сохранность-результатов-закрытой-сессии) / [D-02](../DESIGN_DECISIONS.md#d-02-сериализация-изменений-сессии-и-атомарное-служебное-прерывание): запрет добавления подходов в неактивную (завершённую или прерванную) сессию.
  - [SR-04](../SECURITY_REQUIREMENTS.md#sr-04-независимость-сессий-и-истории-от-редактирования-шаблона) / [D-03](../DESIGN_DECISIONS.md#d-03-неизменяемый-снимок-плана-тренировочной-сессии): независимость структуры активной сессии от последующего редактирования исходного шаблона за счёт фиксации неизменяемого снимка (`SessionExerciseSnapshot`).
- Обеспечивающий механизм:
  - Доменная модель с инкапсулированными переходами состояний: [WorkoutSession.cs](../../src/Gymshinary.Bot/Domain/Entities/WorkoutSession.cs).
  - Прикладной сервис и разделение контрактов по ISP: [IWorkoutService.cs](../../src/Gymshinary.Bot/Services/IWorkoutService.cs), [IOperatorWorkoutService.cs](../../src/Gymshinary.Bot/Services/IOperatorWorkoutService.cs), [WorkoutService.cs](../../src/Gymshinary.Bot/Services/WorkoutService.cs).
  - Репозиторий в памяти с блокировкой и откатом при имитации сбоя аудита: [InMemoryWorkoutRepository.cs](../../src/Gymshinary.Bot/Services/InMemoryWorkoutRepository.cs).
- Версия и условия: коммит `ae4edd1`, изолированная тестовая среда xUnit без внешней зависимости от Telegram API.

### Проверки и результаты
- Позитивная:
  - `HappyPath_UserCreatesProgramTemplateRunsSessionAndCompletes`: владелец создает программу, шаблон, запускает сессию, фиксирует подходы с автоматическим подхватом веса и завершает тренировку. Ожидаемый и фактический результат: сессия переходит в `Completed`, сохраняются результаты всех подходов.
  - `SR04_ModifyingTemplateDoesNotAffectActiveSessionSnapshot`: подтверждает сохранность неизменяемого снимка активной сессии при редактировании упражнений исходного шаблона.
- Негативная:
  - `SR01_UserCannotAccessOrModifyAnotherUsersData`: попытка чужого пользователя прочитать программу, шаблон или сессию возвращает `null`; попытка создать шаблон в чужой программе, запустить сессию по чужому шаблону, записать подход или завершить сессию отклоняется с `UnauthorizedAccessException`.
  - `SR01_SR02_OperatorInterruptSession_ReturnsTechnicalStatusOnly_AndLogsAction`: не-оператор получает отказ в доступе; оператор без причины получает отказ; при успешном прерывании оператор получает только технический статус (`SessionTechnicalStatus`), а тренировочные подходы сохраняются и доступны владельцу.
  - `SR02_D02_FailureOnOperatorAuditLogSave_RollbacksSessionState`: при имитации сбоя сохранения записи аудита сессия гарантированно откатывается к состоянию `Active`, подходы сохраняются, незавершённая запись не остаётся в хранилище.
  - `SR03_CannotRecordSetInClosedOrInterruptedSession`: попытка записи подхода в завершённую или прерванную сессию отклоняется с `InvalidOperationException`.
  - `D02_ConcurrentSessionStart_OnlyOneSucceeds`: параллельный тест проверяет два запуска сессии, подтверждая правило одной активной сессии (ровно один вызов успешен, второй отклоняется).
  - `InputValidation_InvalidRepsOrWeightThrowsArgumentException`: попытки передать неположительное число повторений или отрицательный/нечисловой вес отклоняются валидацией.
- Команда и условия выполнения: запуск набора тестов [WorkoutServiceSecurityTests.cs](../../tests/Gymshinary.Tests/WorkoutServiceSecurityTests.cs) через тестовый раннер xUnit. Фактический результат: 12 тестов безопасности и сценариев ядра пройдены успешно (всего в решении 15 тестов пройдено, 0 не пройдено).

### Вывод и границы
Подтверждено: серверная логика ядра Gymshinary обеспечивает авторизацию по владельцу (`SR-01`), безопасное служебное прерывание с аудитом (`SR-02`), сохранность результатов закрытых сессий (`SR-03`) и неизменяемость снимка плана активной сессии (`SR-04`). Реализована потокобезопасная сериализация изменений сессии и откат при сбоях (`D-02`).
Границы: параллельный тест подтверждает сериализацию для двух одновременных запусков сессии; запись подхода одновременно с закрытием сессии — отдельный сценарий D-02, подлежащий дополнительной проверке при переходе к постоянному хранилищу. Тест SR-04 подтверждает сохранность снимка активной сессии. Гарантии подтверждены на уровне сервисного слоя и репозитория в памяти; транзакционные свойства при работе с PostgreSQL будут валидироваться на этапе интеграции с СУБД.
