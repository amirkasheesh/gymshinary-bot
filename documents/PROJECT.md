# Паспорт проекта

## Общие сведения

**Название команды:** Gymshinary  
**Название продукта:** Gymshinary  
**Коды участников:** `M1`, `M2`, `M3`  
**Статус ранней калибровки:** `черновик`

## 1. Назначение

Gymshinary — Telegram бот для ведения тренировочных программ и фиксации результатов тренировок. Пользователь заранее создаёт программу и один или несколько шаблонов тренировок, например A и B, с упражнениями, плановым количеством подходов и целевыми диапазонами повторений. Шаблон тренировки это план занятия, он не содержит фактических результатов выполнения. При запуске шаблона продукт создаёт отдельную тренировочную сессию — конкретное занятие с датой, состоянием и собственными результатами. Приложение управляет состоянием сессии, последовательно связывает введённые веса и повторения с упражнениями и подходами и сохраняет фактическую историю независимо от дальнейшего редактирования программы. Изменение программы или шаблона не изменяет уже начатые сессии и результаты прошлых занятий. Во время активной сессии пользователь видит последнее выполнение соответствующего упражнения в завершённой сессии и использует его как ориентир. Для упражнения рабочий вес указывается перед первым подходом; если вес не меняется, в следующих подходах пользователь вводит только количество повторений, а приложение повторно использует выбранный вес и сохраняет его в результате каждого подхода. Главная цель продукта — свести к минимуму количество действий во время тренировки: открыть занятие, увидеть предыдущий результат и записать новый, сохранив при этом структурированную и непротиворечивую историю.

## 2. Граница продукта

### В продукт входит:

- взаимодействие с пользователем через Telegram бота;
- создание и редактирование тренировочной программы;
- создание одного или нескольких шаблонов тренировок внутри программы, например A и B;
- добавление упражнений в шаблон тренировки;
- задание планового количества подходов и целевого диапазона повторений;
- создание тренировочной сессии на основе выбранного шаблона;
- правило не более одной активной сессии на пользователя;
- состояния сессии: `активна`, `завершена`, `прервана`;
- сохранение снимка структуры шаблона при начале сессии, чтобы последующее редактирование программы не меняло уже начатую сессию;
- последовательное прохождение упражнений и подходов;
- отображение последнего результата упражнения из завершённой сессии;
- ввод рабочего веса перед первым подходом упражнения и количества повторений после каждого выполненного подхода;
- повторное использование ранее указанного для упражнения веса, если пользователь его не меняет; этот вес сохраняется в результате каждого подхода;
- возможность изменить рабочий вес перед любым следующим подходом;
- возможность записать фактическое количество повторений вне целевого диапазона: диапазон является ориентиром, а не ограничением;
- новые результаты подходов могут добавляться только в сессию со статусом `активна`; после завершения или прерывания продолжить запись результатов в эту сессию нельзя;
- завершение сессии пользователем даже при выполнении не всех запланированных подходов; невыполненные подходы не создаются как фактические результаты;
- сохранение даты, состояния сессии и результатов каждого выполненного подхода;
- хранение прерванных сессий в общей истории с явной отметкой состояния;
- разграничение доступа к данным по владельцу;
- служебная проверка технического состояния активной сессии оператором;
- прерывание активной сессии техническим оператором с обязательным указанием причины;
- сохранение при прерывании уже записанных подходов и фиксация идентификатора оператора, времени и причины действия;
- PostgreSQL как хранилище данных внутри границы продукта;
- схема базы данных, миграции, конфигурация подключения и настройка доступа к хранилищу.

Дополнительные функции, которые относятся к предметной области продукта, но не входят в минимальное ядро:

- комментарии к выполненному упражнению или сессии;
- временная замена упражнения во время активной сессии с отдельной историей заменяющего упражнения;
- несколько самостоятельных программ у одного пользователя.

### Внешнее окружение и внешние системы:

- платформа Telegram как пользовательский интерфейс и канал доставки сообщений;
- Telegram Bot API.

### Команда сознательно не реализует в текущем проекте:

- отдельное мобильное приложение;
- отдельный полноценный веб интерфейс;
- социальную сеть и взаимодействие между пользователями;
- оплату и платные подписки;
- интеграцию с фитнес-браслетами и часами;
- интеграцию с внешними фитнес-сервисами;
- автоматическое составление индивидуальной программы тренировок;
- автоматические рекомендации по рабочему весу и прогрессии;
- аналитику прогресса, графики, поиск персональных рекордов и отдельный аналитический интерфейс;
- готовую библиотеку тренировочных программ;
- видеоинструкции по выполнению упражнений;
- собственную систему регистрации с логинами и паролями;
- отдельную административную панель.

Асинхронный разбор свободного текста через внешнее API нейросети и брокер сообщений рассматривается только как возможное дальнейшее расширение и не входит в текущую границу проекта.

## 3. Пользователи и доступные действия

Обычный пользователь идентифицируется по Telegram аккаунту и является владельцем своих программ, шаблонов тренировок, сессий и результатов. Доступ к данным другого пользователя определяется принадлежностью объекта и не образует отдельную роль.

Технический оператор имеет отдельные служебные полномочия. Источник этих полномочий — серверная конфигурация со списком разрешённых Telegram ID операторов; пользователь не может назначить себя оператором через команды бота. Знание идентификатора чужой сессии само по себе не даёт права получать сведения о ней или выполнять служебные действия.

| Пользователь или роль | Кто это | Что может делать | Что ему недоступно |
| --- | --- | --- | --- |
| Пользователь | Пользователь Telegram, работающий со своими данными | Создавать и редактировать свою программу и шаблоны; запускать и завершать собственные сессии; записывать результаты; просматривать собственную историю; использовать дополнительные функции, если они реализованы | Читать, изменять или удалять программы, сессии, результаты и комментарии других пользователей |
| Технический оператор | Назначенный технический оператор сервиса; для собственных тренировок имеет обычные пользовательские права | По идентификатору сессии проверить её технический статус; прервать активную сессию с обязательным указанием причины; получить подтверждение результата служебной операции | Читать чужие веса, повторения и комментарии; изменять результаты подходов; изменять программу пользователя; отмечать чужую сессию успешно завершённой; выполнять служебное действие без проверки операторских полномочий |

При служебном прерывании сессии уже записанные результаты сохраняются, сессия получает состояние `прервана`, а продукт фиксирует оператора, время и причину действия.

## 4. Сквозные сценарии

### Сценарий 1. Создание тренировочной программы и шаблона

- **Участники:** пользователь.
- **Начальное условие:** пользователь начал работу с ботом и ещё не имеет нужной программы либо хочет изменить существующую.
- **Основные действия:** пользователь создаёт программу, добавляет в неё один или несколько шаблонов тренировок, например A и B, добавляет упражнения и задаёт для них плановое количество подходов и целевой диапазон повторений.
- **Результат:** создана программа с шаблонами, на основе которых можно запускать конкретные тренировочные сессии.
- **Какие данные или состояние изменяются:** создаются или изменяются программа, шаблоны, упражнения и плановые параметры. Изменения не распространяются на уже начатые и прошлые сессии.

### Сценарий 2. Проведение, завершение и восстановление тренировочной сессии

- **Участники:** пользователь; технический оператор — только в ветке восстановления.
- **Начальное условие:** у пользователя существует программа как минимум с одним шаблоном и нет другой активной сессии.
- **Основные действия:** пользователь выбирает шаблон и запускает сессию. Продукт создаёт сессию в состоянии `активна` и фиксирует снимок структуры выбранного шаблона. Для каждого упражнения бот показывает последнее выполнение этого упражнения в завершённой сессии, если такое существует. Перед первым подходом упражнения пользователь указывает рабочий вес. После каждого подхода он вводит количество выполненных повторений. Если вес не меняется, приложение использует ранее указанный для упражнения вес и сохраняет его вместе с результатом нового подхода; если вес изменился, пользователь указывает новое значение перед соответствующим подходом. Фактическое число повторений может выходить за целевой диапазон. Пользователь может завершить занятие, даже если выполнил не все запланированные подходы; перед завершением бот может предупредить о невыполненной части плана.
- **Обычный результат:** сессия получает состояние `завершена`; сохраняются дата, снимок плана и все фактически записанные подходы.
- **Ветка восстановления:** если активная сессия технически зависла и пользователь не может продолжить работу, оператор после проверки своих полномочий запрашивает технический статус по идентификатору сессии и может прервать её с указанием причины. Уже записанные подходы сохраняются, сессия получает состояние `прервана`, дополнительно фиксируются оператор, время и причина действия. Оператор не может этой командой читать содержимое результатов или отметить сессию завершённой.
- **Какие данные или состояние изменяются:** создаётся сессия, меняется её состояние, добавляются результаты выполненных подходов; при операторском прерывании создаётся запись служебного действия.

Правила продукта: у одного пользователя одновременно может существовать не более одной сессии в состоянии `активна`. Для начала новой сессии предыдущая должна быть завершена или прервана. Новые подходы добавляются только в активную сессию; после перехода сессии в состояние `завершена` или `прервана` добавлять или продолжать запись подходов в неё нельзя.

### Сценарий 3. Просмотр истории упражнения

- **Участники:** пользователь.
- **Начальное условие:** пользователь ранее хотя бы один раз выполнял выбранное упражнение.
- **Основные действия:** пользователь выбирает упражнение и запрашивает историю. Бот показывает даты, состояние соответствующих сессий, рабочие веса и количество повторений в сохранённых подходах.
- **Результат:** пользователь получает историю собственных выполнений и может сравнить результаты занятий.
- **Какие данные или состояние изменяются:** постоянное состояние продукта не изменяется; выполняется чтение сохранённой истории.

Под «предыдущим результатом», который показывается во время активной сессии, понимается последнее по времени выполнение соответствующего упражнения в сессии со статусом `завершена`. Прерванные сессии сохраняются в общей истории с отметкой состояния, но не используются как предыдущий результат для следующего занятия.

Если функция замены упражнения будет реализована, результаты основного и заменяющего упражнения хранятся раздельно и не смешиваются.

## 6. Компоненты и внешние взаимодействия

Предполагаемые части продукта:

1. **Серверное приложение Gymshinary**
   - содержит предметную логику программ, шаблонов и сессий;
   - проверяет владельца пользовательских данных;
   - управляет переходами состояний сессии;
   - сохраняет снимок шаблона при старте сессии;
   - определяет предыдущий результат упражнения;
   - реализует служебную операцию прерывания сессии;
   - взаимодействует с PostgreSQL.

2. **Telegram адаптер внутри серверного приложения**
   - принимает поступившие через Telegram Bot API обновления;
   - преобразует команды, сообщения и нажатия кнопок в действия приложения;
   - передаёт в предметную логику идентификатор пользователя и введённые данные;
   - формирует ответы для отправки через Telegram Bot API.

3. **Хранилище данных PostgreSQL**
   - находится внутри границы продукта и входит в ответственность команды;
   - хранит пользователей, программы, шаблоны, сессии, снимки шаблонов, результаты подходов и записи действий операторов;
   - при реализации дополнительных функций хранит комментарии и сведения о заменах упражнений;
   - использует проектируемую командой схему данных, миграции и настройки доступа.

4. **Серверная конфигурация**
   - содержит параметры подключения и список Telegram ID, которым разрешена роль технического оператора;
   - не изменяется командами обычного пользователя через Telegram.

5. **Telegram и Telegram Bot API — внешние системы**
   - Telegram доставляет пользовательские сообщения и отображает ответы;
   - Telegram Bot API передаёт серверному приложению Telegram ID, команды, сообщения и callback данные;
   - серверное приложение передаёт обратно текст ответов и элементы управления.

Основной пользовательский поток:

`Пользователь - Telegram - Telegram Bot API - Telegram адаптер - предметная логика Gymshinary - PostgreSQL`

Служебный поток:

`Технический оператор - Telegram - Telegram Bot API - Telegram адаптер - проверка операторских полномочий - служебная операция с сессией - PostgreSQL`

Передаваемый идентификатор сессии используется только как ссылка на объект. Перед выполнением чтения технического статуса или прерывания сервер отдельно проверяет операторские полномочия; знание идентификатора не является основанием доступа.

| Источник | Пример данных | Кто управляет источником | Как продукт использует данные |

| Telegram Update | Telegram ID, команда `/start`, callback данные, сообщение | Telegram и пользователь | Идентификация пользователя и определение требуемого действия |
| Команды и кнопки пользователя | Создать шаблон, начать сессию, записать подход, завершить сессию | Пользователь | Управление пользовательскими сценариями и состоянием собственной сессии |
| Ввод параметров программы | Название шаблона, упражнение, количество подходов, целевой диапазон повторений | Пользователь | Создание и изменение программы и шаблонов |
| Ввод во время сессии | Рабочий вес перед первым подходом упражнения или при его изменении; количество повторений после каждого подхода; при реализации дополнительной функции — комментарий | Пользователь | Формирование истории фактически выполненных подходов; при отсутствии нового значения веса используется ранее выбранный для этого упражнения вес |
| Служебная команда оператора | Идентификатор сессии, команда проверки статуса или прерывания, причина | Технический оператор | Проверка технического статуса и перевод активной сессии в состояние `прервана` после проверки полномочий |
| Серверная конфигурация операторов | Список разрешённых Telegram ID операторов | Команда проекта / среда развёртывания | Определение наличия технических полномочий; пользовательский ввод не может предоставить эти права |
| Сохранённая история | Результаты и состояния прошлых сессий | Сам продукт на основании ранее сохранённых данных | Просмотр истории и выбор последнего выполнения упражнения в завершённой сессии |
| Системное время | Время старта, завершения или прерывания сессии | Среда исполнения | Привязка событий и операторских действий ко времени |

## 8. Минимальное функциональное ядро

### Обязательные функции:

- идентификация пользователя через Telegram ID;
- разграничение доступа к пользовательским данным по владельцу;
- создание и редактирование тренировочной программы и её шаблонов; пользователь может начать с одного шаблона и при необходимости добавить другие;
- добавление упражнений и настройка планового количества подходов и целевого диапазона повторений;
- создание сессии на основе шаблона с сохранением снимка его структуры;
- правило не более одной активной сессии на пользователя;
- состояния сессии `активна`, `завершена`, `прервана`;
- ввод рабочего веса перед первым подходом упражнения с его сохранением для следующих подходов;
- ввод количества повторений после каждого подхода без повторного ввода веса, если вес не изменился;
- возможность изменить рабочий вес перед отдельным подходом;
- сохранение фактического веса в результате каждого записанного подхода;
- возможность записывать фактическое количество повторений вне целевого диапазона;
- добавление новых подходов только в сессию со статусом `активна`; после завершения или прерывания запись новых подходов запрещена;
- завершение сессии пользователем без требования заполнить каждый запланированный подход;
- сохранение истории сессий и результатов независимо от последующего редактирования программы;
- отображение последнего результата упражнения из завершённой сессии;
- просмотр простой истории упражнения с состояниями сессий;
- техническая проверка состояния сессии оператором по идентификатору после проверки его полномочий;
- прерывание оператором активной сессии с сохранением записанных подходов;
- фиксация оператора, времени и причины служебного прерывания;
- запрет служебным командам оператора читать чужие веса и комментарии, изменять результаты или отмечать сессию успешно завершённой.

### Дополнительные функции, которые можно исключить при нехватке времени:

- комментарии к упражнениям и сессиям;
- замена упражнения во время активной сессии;
- несколько самостоятельных программ у одного пользователя.

### За пределами текущего проекта:

- аналитика прогресса, графики, поиск персональных рекордов и отдельный аналитический интерфейс;
- автоматические рекомендации по прогрессии и рабочему весу;
- автоматическое составление индивидуальных программ;
- готовая библиотека программ;
- разбор свободного текста через API нейросети и брокер сообщений.

После исключения дополнительных функций сохраняются предметная логика программы, шаблонов и сессий, изменяемое состояние, история результатов, разграничение доступа и ветка технического восстановления.

## 9. Стек и путь к первой работающей версии

**Основные технологии:** C# / .NET 8, Telegram Bot API, библиотека Telegram.Bot, PostgreSQL, Entity Framework Core, xUnit, Docker Compose.  

**Технологии, новые для команды:** Entity Framework Core и xUnit.  

**Внешние сервисы, необходимые для пользовательского Telegram-интерфейса:** Telegram Bot API. Основная предметная логика и работа с PostgreSQL должны проверяться без доступности Telegram.  

**Как основные сценарии будут запускаться и проверяться при недоступности внешних сервисов:** PostgreSQL запускается локально через Docker Compose. Тесты xUnit обращаются к прикладной логике через локальный тестовый адаптер, передавая действия тестовых пользователей и технического оператора без Telegram Bot API. В тестовой конфигурации явно задаются идентификаторы владельцев данных и разрешённого оператора, что позволяет проверять создание программы, запуск и переходы состояний сессии, разграничение доступа и служебное прерывание.

**Что команда реализует первым, чтобы получить запускаемую версию:** серверную основу, которая локально подключается к PostgreSQL, применяет схему данных и позволяет через прикладной слой создать программу с шаблоном и получить её обратно из БД без Telegram. После этого к работающей предметной логике подключается Telegram адаптер и минимальный пользовательский сценарий.
