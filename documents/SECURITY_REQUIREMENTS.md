# Требования безопасности Gymshinary

## SR-01. Доступ к пользовательским данным по владельцу

**Требование.** Читать содержимое тренировочной программы, шаблона, сессии и результатов подходов может только их владелец. Изменять эти объекты может только владелец в пределах разрешённых действий; исключение составляет служебное прерывание сессии по SR-02. Оператору доступен только технический статус чужой сессии, но не её веса и повторения. Указание идентификатора чужого объекта не предоставляет доступ к его содержимому или изменению.

**Защитный смысл.** Чужой доступ раскроет сведения о тренировках и физических результатах либо исказит сохранённую историю пользователя.

**Критерий приёмки.** Пользователь B, зная идентификаторы объектов пользователя A, запрашивает его программу, шаблон, сессию и результаты подходов, пытается изменить программу или шаблон A и записать подход в сессию A. Бот не показывает чужие данные и отклоняет изменения; программа, шаблон, состояние сессии и результаты A остаются прежними. Пользователь A может просмотреть собственные данные, выполнить допустимое редактирование программы и шаблона и записать подход в собственную активную сессию. При запросе сессии A назначенный оператор получает только её технический статус, без содержимого программы, шаблона, весов и повторений A.

**ASVS:** [v5.0.0-8.2.2](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.flat.json). Доступ к конкретным объектам данных предоставляется только при наличии соответствующих полномочий.

## SR-02. Контролируемое служебное прерывание сессии

**Требование.** Прервать активную сессию через служебную операцию может только назначенный технический оператор, указав непустую причину. Причина из одних пробелов считается отсутствующей. При успешном прерывании система сохраняет прежние результаты подходов и фиксирует, какой оператор прервал какую сессию, когда и по какой причине. Не допускается сохранённое служебное прерывание без соответствующей записи действия, в том числе при сбое во время операции. Знание идентификатора сессии не предоставляет служебных полномочий.

**Защитный смысл.** Несанкционированное прерывание лишит пользователя возможности продолжить тренировку. Без записи об операторе, времени и причине невозможно проверить обоснованность служебного вмешательства.

**Критерий приёмки.** Обычный пользователь B, зная идентификатор активной сессии пользователя A, пытается выполнить служебное прерывание: действие отклоняется, статус и записанные подходы не меняются. Назначенный оператор пытается прервать эту сессию без причины или с причиной из одних пробелов: действие также отклоняется, статус и подходы остаются прежними. При прерывании тем же оператором с указанной причиной сессия получает статус `прервана`, ранее записанные подходы остаются прежними, а запись служебного действия содержит идентификаторы оператора и сессии, время и причину. При искусственном сбое сохранения записи служебного действия не остаётся сессии, прерванной этой операцией без такой записи; прежние подходы сохраняются.

## SR-03. Сохранность результатов закрытой сессии

**Требование.** Новые результаты подходов можно добавлять только пока сессия находится в состоянии `активна`. После завершения или прерывания сессии добавление подходов в неё запрещено, а ранее записанные результаты сохраняются. Ограничение действует и при одновременной обработке записи подхода и закрытия сессии: подход не должен сохраняться после уже сохранённого перехода сессии в закрытое состояние. Ограничение доступа к сессии по владельцу задано в SR-01.

**Защитный смысл.** Запись после закрытия исказит историю фактически выполненной тренировки. Для завершённой сессии это также исказит предыдущий результат, который бот показывает в следующих занятиях.

**Критерий приёмки.** После завершения или прерывания собственной сессии её владелец повторно отправляет команду либо нажимает старую кнопку для записи подхода. Бот отклоняет действие; статус, количество подходов, веса и повторения остаются прежними. При одновременной обработке закрытия и записи подхода, если переход в закрытое состояние уже сохранён, новая запись не сохраняется. Пока собственная сессия активна, допустимый подход в неё записывается.

## SR-04. Независимость сессий и истории от редактирования шаблона

**Требование.** При запуске сессии система сохраняет снимок структуры выбранного шаблона. Последующее редактирование программы или шаблона не изменяет этот снимок, состояние сессии и уже записанные результаты. Ограничение относится к активным, завершённым и прерванным сессиям. Изменённый шаблон используется для новых сессий.

**Защитный смысл.** Без независимого снимка обычное редактирование плана может незаметно изменить уже начатое занятие или содержание прошлой истории. Результаты окажутся связаны с другим планом, и пользователь получит неверные сведения о выполненной тренировке.

**Критерий приёмки.** Пользователь A запускает сессию по шаблону и записывает подход. Затем он изменяет состав упражнений и плановое количество подходов в исходном шаблоне. Снимок активной сессии, её состояние и записанный результат остаются прежними. Аналогичное редактирование не меняет снимки и результаты завершённых и прерванных сессий. Новая сессия, запущенная после допустимого закрытия активной, содержит обновлённый план.
